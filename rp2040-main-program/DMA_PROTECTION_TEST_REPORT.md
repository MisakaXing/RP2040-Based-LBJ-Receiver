# DMA、温度与低电量保护验证

> 本文保留保护功能阶段的原始测试记录。后续 DMA/AFC 修复与 5.11 / 5.13-W 提交前验证见 `DMA_RECOVERY_TEST_REPORT.md`；下文版本和“未推送”状态对应当时测试阶段。

日期：2026-10-04。普通版 5.10；W 版 5.12-W。两台设备已刷写，未提交或推送 GitHub。

## 行为

| 条件 | 两版行为 | W 版附加行为 |
| --- | --- | --- |
| 核心温度 >45°C | 温度读数标红 | 相同 |
| 核心温度 >60°C | 顶栏红色 HIGH TEMP | 关闭 AP；无线设置显示高温禁用原因 |
| 温度降至 ≤55°C | 解除无线高温锁定 | 依照原先保存的无线开关恢复；不会擅自开启原本关闭的无线 |
| 电池 <10%，无 USB 供电 | 顶栏红色 LOW BAT | 相同 |
| >60°C 且 <10%，无 USB 供电 | 两项警告每 2 秒交替 | 相同 |
| 电量 0%（补偿后的电压 ≤3.45 V），无 USB 供电 | 提示停收约 1 秒，关闭射频采集与屏幕，确认停收后降至 18 MHz | 同时关闭 AP |
| 保护后检测到 USB 供电 | 连续两次确认后硬件重启，重新完成 POST | 相同；保留原设置 |

普通版保留原 +0.174 V 电池补偿；W 版保留 1.07 倍补偿。普通版正常运行 200 MHz，W 版 150 MHz，不改变正常接收频率或射频参数。USB 状态每秒采样；温度与电池每 5 秒采样。警告交替与局部重绘无阻塞等待；仅低电量终止接收流程包含提示和保护等待。

## DMA

普通版已移植 W 版的 PIO→DMA 采集路径：512 个 32 位字的环形缓冲，两个 DMA 通道。运行时检查 DMA 支持，初始化失败回退原 FIFO。保留溢出与丢字计数，不把“队列没有丢弃”等同于射频完全没有丢码。

停收时关闭 PIO、数据与重载 DMA，并使 SX1276 进入 FSK Sleep。射频参数仍为 821242368 Hz、PPM 6、12.5 kHz 带宽、硬件 AFC、AGC 关闭、LNA 0x23。PicoUpdater 已同步模块清单及刷写顺序；仍兼容旧版固件包。

## 实机专项

普通板 S/N：e66368254f677426。W 板 S/N：018540bc4336e6b4。

两板实测 DMA 连续有序字、环形回绕、重载计数、故意溢出计数及停止/重置。以独立 PIO 状态机生成输入，暂停消费 1.5 秒仍保存 56 个字，PIO FIFO 未满。

两板实际执行 LCD 警告绘制、射频与 DMA 停止、射频 Sleep、关闭背光、18 MHz 降频及重启恢复。温度、电量和保护中的 USB 插入返回值采用 RAM 注入，不加热设备、不耗尽电池，不制造历史车次。W 板实际关闭/恢复 AP，并验证无线高温提示及 55°C 回差。

最初 W 板在停收退出 core 1 后的保护流程出现 USB 无响应。改为停收后让 core 1 保持空闲驻留，避免退出线程；修改后完整通过 18 MHz 保护与 USB 重启路径。结果不支持“18 MHz 必然过低”，但底层线程退出/Flash 锁定关联仍是推测，未证明具体固件根因。生产代码没有加入测试用看门狗。

停收异常分支已加回归测试：只有 receiver.stop 成功才确认已停收；若失败，保护不执行降频。

## 普通版六分钟联合测试

按正常接收→历史翻页→正常接收→模拟高温低电量并翻页运行。实际绘制 273 次历史翻页，历史条数 1204→1222，持续接收真实射频车次。两项顶栏警告均出现。

DMA 溢出、DMA 丢字、FIFO 满、接收线程异常及 UI 队列丢弃均为 0；DMA 峰值 14/512 字。仍存在无线信道 BCH 不可纠正码字及重同步，不能据此断言所有空中报文均成功接收。

首次逐行核验 1229 条落盘 JSON 均有效；追加接收后的最终核验为 1274 条，仍无无效行，首/中/末记录读取正确，待写队列清零。设备主程序和新模块与本地逐字节一致，移除临时测试入口后硬件重启恢复正常 DMA 接收。检查脚本曾误将 REPL 的不可变总数快照当作实时计数；已改为与实际可变索引长度对照，确认不是历史文件损坏。

## W 版六分钟联合测试

同样执行四阶段对照，机内历史共绘制 316 次（正常 157、高温低电量 159）；SSE 所有者发起 119 次历史请求，其中 118 次完成，阶段切换时最后一项主动取消，无错误响应。温度注入 61.2°C 时实际 AP 关闭，HIGH TEMP/LOW BAT 均出现；恢复真实温度 43.4°C 后，按原保存的开启状态恢复 AP。

初始无同步，出现此前已存在的 profile_op_mode 恢复；约第 5 分钟才开始捕获射频。历史 1639→1640，采集超过 2600 个字；DMA 溢出、丢字、FIFO 满、UI/历史队列丢弃、线程异常、网页及存储错误为 0。仍存在 BCH 错码和重同步，不能承诺全报文接收。此轮没有在“网页历史负载开启”阶段获得实际射频车次，因此不单凭本轮证明该组合下接收性能完全不受影响。

最终逐行核验 1640 条历史全部有效，首/中/末记录可读取，待写队列为 0；七个部署文件逐字节核验，正常主程序已恢复，无临时测试入口。硬件重启后 AP 与 512 字 DMA 接收正常初始化。
