# W 网页历史回放与 DMA 验证

> 本文保留网页历史功能阶段的原始测试记录。两版最新 DMA/AFC 修复与 5.11 / 5.13-W 提交前验证见 `DMA_RECOVERY_TEST_REPORT.md`；下文版本和“未推送”状态对应当时测试阶段。

日期：2026-10-04。最终候选版已刷入，联合测试及最终核验完成，已硬件重启恢复接收；未提交、未推送 GitHub。普通版固件未修改。

## 实现范围

- 保留唯一 SSE 长连接与实时轮询架构。只有 SSE 所有者收到随机会话令牌，并绑定来源 IP；其他页面只能轮询实时信息，禁用历史按钮并说明原因。
- 首次上/下翻显示最新已保存记录，此后循环翻页，每次一条。返回或 20 秒无操作回到实时；回放时新车次仍更新后台、本机和声音提醒，不覆盖历史内容。
- 处理断线、授权撤销、空历史、索引变化、迟到响应、读取失败、有限忙重试和主动取消。
- 导航按钮 46 px，声音按钮 44 px；手机单列，平板/电脑双列。
- 历史文件、索引格式、本机游标、缓存与实时快照不因网页回放而改变。

## 接收与屏幕保护

- 网页服务在本机列车重绘、按键、历史超时之后运行。
- 原始解码、UI、历史落盘或 SD 队列非空，输入积压超过一个字，或距离存储操作不足 80 ms 时，不读网页历史。
- DMA 正常运行时允许射频线程继续处理；硬件仍采集输入，读取每次最多一行，步骤至少间隔 40 ms。没有 DMA 时额外要求射频线程空闲、已同步时有至少 100 ms 输入间隔。
- 收到请求时先创建不执行 Flash 读取的生成器，等待安全窗口；3 秒无足够进展返回忙。网页最多重试 8 次，仍可取消，20 秒无操作会退出。
- 不调整射频寄存器、PPM、带宽、AGC、CPU 150 MHz、LCD SPI 请求值 60 MHz 或电池补偿 1.07 倍。最终 SPI 对象实际报告 24 MHz；此次没有修改 SPI 初始化或屏幕库，不能把请求值当成实际输出频率。
- 这些措施和有限测试窗口不是长期绝对无漏收、零额外延迟的保证。

## DMA

- PIO RX 由硬件搬至对齐 512 字环形缓冲：有效 2 KB，对齐分配约 4 KB；1200 bit/s 下约容纳 13.65 秒输入。
- 两个 DMA 通道负责接收与计数硬件重装，不使用 Python IRQ 重装，不新增 Python 线程。
- 正常计数模式、缓冲强引用、地址对齐；停止时先清 EN 再 abort，处理 RP2350-E5。
- 记录积压、高水位、溢出及丢失字数；真实溢出会丢弃最旧字并重置解码同步，避免拼接断裂数据。
- 射频恢复、低电量停收同时停止/重置 DMA；不支持或初始化失败时记录警告并回退 FIFO 路径。
- PicoUpdater 的 W 文件清单加入可选 pio_dma_rx.py，上传顺序在 main.py 之前；旧 W 发布仍可安装。普通版清单不带该模块。

硬件启动自测通过：96 字顺序、小计数硬件重装与回绕；8 字环注入 11 字，准确报告丢 3 字、保留最新 8 字；停止、重置、关闭通过。消费者暂停 1.5 秒期间，512 字环完整保留 57 个合成连续字，顺序正确，FIFO 为 0。自测在 Wi-Fi 和射频线程启动前执行，先恢复正常 main.py 并移除临时启动文件，再运行试验。

## 实机联合测试

RP2350B PLUS W，S/N 018540…e6b4。实际 Wi-Fi AP 开启，射频 core 1、屏幕、本机 Flash 落盘和门户服务同时运行；压力 HTTP 对端是 RAM 模拟 socket，运行生产门户状态机，不是手机经过热点的网络流量。

已完成三轮六分钟 A/B/A/B，累计 18 分钟；只有最后一轮是最终候选版。每轮 A1 60 秒、B1 120 秒、A2 60 秒、B2 120 秒。

第一轮 DMA + 严格忙窗口：历史成功 6 / 5，忙响应 377 / 453；FIFO 满、DMA 溢出/丢字、队列丢弃、线程/SPI/回调/网络/存储错误均为 0；DMA 高水位 30 字。读取避让过严导致历史体验不可用，未采用。

第二轮接收忙先挂起、DMA 放宽无输入间隔，但仍等待线程空闲：历史成功 14 / 14，忙超时 30 / 29；同样无 FIFO 满、DMA 丢字或程序错误，高水位 31 字。查询成功率仍不足，因此最终版仅在 DMA 健康、无输入积压和优先队列时允许并行分步读取。

历史成功共 217 次、忙超时 8 次；阶段结束时另外取消两条尚在处理的测试请求。历史超时属于有界的接收/存储避让，不是接收队列丢弃；网页会自动重试。网页单次服务最大 38 ms；压力阶段 UI 循环最大 357 ms，基准最大 366 ms；压力重绘最大 202 ms，基准最大 199 ms，不能据此声称绝对零附加耗时。

最终 DMA 高水位 28 / 512 字，FIFO 满、DMA 溢出/丢字、原始/UI/历史/SD 队列丢弃、线程/SPI/回调/网络/存储错误均为 0，射频最长 tick 间隔 767 ms（数据仍被 DMA 保存）。两段基准共重绘 28 次，两段压力重绘 51 次。实际信号仍有 BCH 纠错失败、重同步和损坏报文，不能把缓冲正常等同于所有空中报文成功解码。

## 最终核验与限制

- 最终 main.py、wireless_portal.py、history_store.py、boot_post.py、lbj_receiver.py、pio_dma_rx.py 六个机内文件与本地逐字节一致。临时压力/启动探针及启动回退文件均不存在。
- 实际 MicroPython/Flash 复核唯一 SSE、来源 IP、第二页轮询、未授权拒绝、撤销、忙响应、最新/首尾循环通过；每一步最大 12–13 ms。最终历史 1004 条、坏记录 0、索引完整，未清除历史；测试中真实射频持续新增记录。
- 停止射频线程后 PIO 与 DMA 确认停用；CPU 150 MHz、电池补偿 1.07、AP 请求功率 31 和屏幕 SPI 配置保持原值。最终硬件重启重新打印 RADIO_DMA_READY，真实射频重新同步，无线程/SPI/回调/网络/存储错误。
- Mac 网络未切换，因此未完成外部多手机通过 W 热点的端到端测试，也没有最终人工按键/屏幕确认。
- 早期无 DMA 长测曾有 FIFO 满；也曾失去 USB 响应。用户后来确认数据线脱落，串口重枚举为 /dev/cu.usbmodem1101。不能据此断言所有断连由代码或 DMA 导致；后续使用硬件重启及按 S/N 选择串口。
- 测试后仍保留正常 DMA 接收程序，不保留临时自测/压力探针，不推送 GitHub。

## 接收日期与分钟显示追加修正

- 历史回放顶部突出显示“接收于 YYYY-MM-DD HH:MM”，详情接收时间一致且不显示秒。回放时 SSE 新车次只更新后台与本机状态，不覆盖历史时间；返回、超时和断线后隐藏历史日期标题。
- 实时网页快照与机内记录共用同一次 RTC 日期/分钟读取；不新增 RTC 采样，SD 日志保持原秒级格式。
- 旧时间-only 记录用未知日期占位，不拿当前日期补造；缺失时间也明确占位。
- 201 项固件测试通过；真实 TCP/Chrome 三页面、20 秒返回、日期不被 SSE 覆盖及四尺寸布局检查通过。390×844 历史示例仍可一屏容纳。
- W 板 main.py、wireless_portal.py 写入后回读一致。重新启动后的 MicroPython 校验秒截取、旧记录/未知日期、实际首尾历史和实时快照通过：首条 2026-10-03 21:51，末条 2026-10-04 14:33；1144 条历史、坏记录 0、线程错误 0。随后硬件重启恢复接收，DMA 重新启用。
- 上述 18 分钟对照在此次时间显示修正之前；此次没有重复该长压力测试，仅完成日期专项及短窗口接收检查。射频、DMA 和屏幕驱动没有改动，仍未推送 GitHub。
