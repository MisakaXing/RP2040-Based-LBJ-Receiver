# 普通版 5.12：历史容量与剩余空间保护

日期：2026-10-05（北京时间）。本次只更新普通版，未改 W 版或射频/DMA 配置。

## 行为

- 历史上限及 ABOUT 页同步为 2000 条；不会自动覆盖或截掉旧记录。
- 预留 16 KiB（不是 5 KiB）。写入前按 `statvfs` 的可用块数检查空间，额外计算本条 UTF-8 JSON 需要的整块空间及两个写入周转块。
- 达到条数上限或空间不足，持续显示红色 `MEM FULL`，停止历史队列和 Flash 追加；实时解码、显示和独立 SD 日志不受此限制。
- 文件系统读取、空间检查或写入异常显示 `SAVE ERR`，停止反复重试。只有写入与关闭/flush 均成功才发布索引、增加条数。
- 格式化历史后重新建立索引并检查空间，允许恢复保存。重启也重新检查；未完成的尾行会阻止继续追加，不会悄悄删除。
- 2000 是最大条数，不承诺任意长度的完整报文都能存满：若实际空间先不足，则提前保护。

## 普通 Pico 实机

1. **Unicode 保存/索引：通过。** 两条含中文车型的 JSON 实际写入临时文件；第二条字节偏移与第一条实际长度一致，读取内容相同。
2. **真实 2000 条边界：通过。** 临时文件中先写入并扫描 1999 条短样本，随后使用生产保存函数写入第 2000 条；索引和条数均为 2000。再尝试 10 次保存/入队均被拒绝，文件大小保持 278,000 字节，末条可正确读取。此测试不意味着 2000 条长 FULL DATA 报文必然放得下。
3. **真实低空间：通过。** 使用临时填充文件将实际 Flash 空闲压至 24,576 字节。生产策略在追加前触发保护，历史文件仍为空、索引和计数均为零；后续入队被拒绝。此次拒绝约 9.8 ms。
4. **空间恢复：通过。** 清除临时填充文件后保护仍锁存；按格式化同样的初始化路径重新检查，保存恢复正常。
5. **PIO/DMA—解码—LCD—Flash：通过。** 32 个不同车次的已知完整 POCSAG 样本通过实际 PIO 状态机、DMA 和生产解码器，不是直接注入 UI 回调。正常保存阶段 16 条全部更新屏幕并落盘；RAM 中模拟空间保护阶段另外 16 条仍更新屏幕、但新增历史为零。同步增加 32，不可纠正码字增加 0，DMA 溢出/丢弃、回调错误及 UI 丢弃均为 0。存储服务最大用时约 138 ms。
6. **清理、重启、读回：通过。** 全部临时填充/样本文件已删除，真实历史未被测试样本污染。机内 5.12 `main.py` 与提交源码逐字相同，射频/DMA/保护依赖与本地相同，配置与升级前备份逐字相同；最后硬件重启恢复正常程序。

第 5 项为数字接收链路测试，不是空口发射、天线或现场接收率测试。测试脚本仅在 RAM 中使用无 GPIO 输出的 PIO 数据源，结束后硬件重启撤销全部测试状态；未改写射频库、DMA 库或配置文件。
