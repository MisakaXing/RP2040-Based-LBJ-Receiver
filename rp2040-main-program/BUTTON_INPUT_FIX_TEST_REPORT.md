# W 版按键事件保留与无线让行测试

日期：2026-10-05。设备：Waveshare RP2350B Plus W。设备 S/N 同时用于热点密码，不在公开报告中披露。
板上测试版本标识为 `5.13-W`，发布版递增为 `5.14-W`；发布与实测代码仅版本字符串不同，普通版未改动。2026-10-05 用户确认“测试无问题”，授权提交并推送 GitHub。

## 修改范围

- 五键使用双边沿硬 IRQ 保存电平、时间及一个待处理按下事件，命令仍只在核心 0 执行。IRQ 不绘屏、不写 Flash、不操作无线、不分配堆对象；异常缓冲区在启动阶段预分配。
- 消抖维持 12 ms；完整短按即使发生在两次扫描之间也保留。忙碌期间同键多次按下合并为一次，避免恢复时重放确认或无线开关。长按重复不补发积压次数。
- 主循环先处理已解码的真实列车事件，再处理按键；非必要状态重绘、Flash、检查点、GC、无线服务排在后面。扫描使用实际执行时刻，不能沿用之前 I/O 开始前的旧时间。
- MENU 与缓存的方向／OK 同时出现时，MENU 优先，避免打开菜单的同时确认新页面。
- 无线 DNS、HTTP、accept、AP 状态检查轮转执行；总协作预算 8 ms。有射频原始队列、显示队列、DMA 待处理积压或待处理按键时让行。
- 8 ms 是协作预算，不是能够中断单次 SDK 调用的强制超时。如果底层调用迟迟不返回，仍可能延迟界面处理；IRQ 仅保留该期间的短按，不能强制打断 SDK。
- 每分钟输出 `BUTTON_HEALTH`，记录硬 IRQ 是否启用、捕获／处理／合并计数、最长扫描间隔和最长无线服务耗时。

## 射频优先与未改动的路径

逐函数 AST 对比确认 `radio_core_task`、`on_lbj_data`、`process_ui_data`、`service_history_storage` 与原提交一致。`lbj_receiver.py`、`pio_dma_rx.py`、`history_store.py` 完全未修改。没有更改 PPM、带宽、AGC、频率、SPI、PIO、DMA 参数，也没有让核心 0 消费 DMA 数据。网络待处理量查询仅用于让行。

原生 MicroPython 源码核验：硬 IRQ 分发锁定调度器及堆分配，GC 锁深度按线程保存；此处是上游机制参考，不能代替对 Waveshare 定制固件的板上验证。

- https://github.com/micropython/micropython/blob/master/py/gc.c

## 板上验证

1. 停机前现场：屏幕开启、DASHBOARD、AP 开启、手机连接数 0；释放状态五键 GPIO 均为 1，软件未处于按住／抑制状态。历史 5337 条，待写 0；DMA 开启，溢出／丢字／原始队列丢弃／射频线程／SPI／回调错误均为 0。这次读取没有保留住用户之前的按键无响应现场。
2. 备份原 main.py 和 wireless_portal.py 后只部署这两个文件；板端 SHA-256 校验匹配。
3. RAM 禁止堆分配测试：100 次完整脉冲，100 次捕获、100 次处理、200 个边沿，无重复。空闲单键 poll 平均约 190 µs，仅是本次板上测量，不代表硬 IRQ 的最大延迟。
4. 首次正式启动五键 IRQ 全部启用；实际历史计数从 5337 增至 5363 后才开始后续观测，满足先确认收到真实车次的要求。
5. RAM 轻量观测 240 秒：最后定时样本从 5363 增至 5391，停止观测时计数为 5401，最新车型从之前 FXD3-J-0419 变为 FXD3-J-0420。DMA 溢出／丢字、原始／UI／历史队列丢弃、线程、存储、无线服务错误均为 0。计数包含尚未落盘的少量记录，不应解释为全部已写入 Flash。
6. 原生 `Pin.irq()` 分发对象调用测试：五键各 100 个完整脉冲，每键捕获／处理／边沿为 100／100／200；期间射频采集继续增加 21 个字，射频线程错误新增 0、DMA 溢出／丢字 0。不驱动 GPIO 输出、不注入模拟车次，不把此项等同于用户实际按键或手机无线端到端测试。临时替换的 IRQ 处理器在 finally 恢复。
7. 最终追加的锁存边沿竞态修复重新部署 main.py，完整性校验匹配；硬件重启清除 RAM 测试与观测程序。启动确认：150 MHz、9999 条容量、5401 条有效历史、0 无效记录、338 个检查点、尾部恢复解析 68 条耗时 428 ms，DMA 环 512 字，五键 IRQ 全启用。正常代码无测试包装器，85 秒观察无线服务最长 6 ms、按键扫描最长 283 ms，所见错误／丢弃计数为 0。没有在设备上保存测试脚本，没有清除历史、索引或设置。
8. 再补做最终代码的板上 UI 集成：通过原生 IRQ 分发和 RAM 模拟输入电平（不驱动 GPIO），执行真实生产主循环及真实 TFT 操作。10 轮、90 个安全按键动作全部通过：MENU 进出、上下选菜单、上下历史／OK 返回、临时 on-demand 模式 POWER 关开屏。额外通过生产无线菜单真实停止／启动 CYW43 AP 一次，并核验设置文件内容与测试前一致。期间射频增加 154 个字，线程错误新增 0，DMA 溢出／丢字、原始／UI／历史队列丢弃均为 0；没有选择格式化、没有注入模拟车次。结束再次硬件重启恢复正式程序。

本轮自动采集的 240 秒日志中，实体按键边沿／事件均为 0、手机连接数均为 0，不能将这段日志当作手机并发测试。后续用户确认“测试无问题”；此项属于用户实测反馈，没有额外并发计时日志。短期验证不能保证长期持续假死已完全排除。

最终 UI 集成结束后的正式启动再次确认：5431 条有效历史、0 无效记录，340 个检查点，尾部恢复 30 条耗时 214 ms；AP 及 512 字 DMA 环正常启动、五键 IRQ 全启用。这 5431 条来自真实接收与正常历史处理，不含测试注入。
