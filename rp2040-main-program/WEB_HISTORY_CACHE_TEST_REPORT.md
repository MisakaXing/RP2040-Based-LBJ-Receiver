# W 网页历史预取缓存

2026-10-04 · 仅修改 W 版，不推送 GitHub。设备仍使用 5.13-W 版本标识。

## 改动

- 首次查询分步预取附近最多 8 条；独立于本机 16 条缓存，不改变屏幕历史游标或最新实时快照。
- 每个冷读取步骤仍最多解析一行，保持 40 ms 间隔并检查接收、屏幕和落盘优先条件。
- 缓存命中保证只读 RAM，可跳过 Flash 的繁忙等待与 40 ms 间隔；HTTP 仍保留 SSE 令牌、来源 IP、退出及格式化失效检查。
- 新记录追加不改变原记录编号，因此已有缓存继续有效；扫描／格式化清空缓存并递增代际，待处理旧请求返回历史已变更。
- 只保留一个最多 8 条的网页窗口；内存回收后不足 48 KiB 不预取，预取中余量不足 16 KiB 或分配失败退回原分步单条读取。
- 没有修改射频寄存器、DMA、CPU 频率、屏幕驱动、按键逻辑、历史文件或索引格式；HTTP 返回仍一次显示一条，不把所有历史下载到手机。

跨出缓存窗口仍需要一次冷读取；靠近尾部或索引块边界可能少于 8 条。缓存消除了重复 Flash 扫描，不消除无线传输延迟。

## 已完成验证

- 固件自动测试 249 项通过，包含预取上限、缓存命中不读 Flash、独立 LCD 缓存、格式化／扫描失效、追加、取消关文件、坏行、不同索引步长、低内存退回、SSE 权限和忙窗口。
- Mac 的 9999 条模拟历史 + 实际 TCP / 原生 EventSource / Chrome 三客户端：首次约 652 ms、下一条缓存命中约 82 ms；命中无 Flash 行读取。还验证第二／第三页面轮询、未授权 403、双向循环、后台新车次、20 秒退出及 SSE 接替。此结果是 Mac 本地服务，不是接收器热点传输时间。
- W 板更新 history_store.py、wireless_portal.py，以及版本号同步为已发布 5.13-W 的 main.py，逐字节回读一致；原接收器、DMA、保护模块及配置核验未变。刷写前记录队列已排空，没有格式化历史。
- W 板真实 Flash 与生产 HTTP 状态机的 RAM 对端测试：首次预取 8 条耗时 418 ms；后续七条为 75、72、65、59、61、61、77 ms，均未再读 Flash。接收线程同时运行，DMA 溢出／丢字、线程／SPI／回调／队列丢弃为 0；没有替换实际射频输入。该短测未获得新同步，不能只据这一项宣称接收性能完全不受影响。
- 缓存纯测中回收后可用 RAM 为 256752→252624 字节，但包含 HTTP 辅助对象，不等同于精确缓存对象大小；没有把此值当作长期最小内存余量。
