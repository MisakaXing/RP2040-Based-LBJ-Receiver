# LBJ Log Viewer

运行 `python3 jsondecode.py`。需安装 `mpremote`、`pyserial`、`customtkinter`、`tkintermapview`，以及 Python 的 Tk 支持。
`jsondecode.py` 与 `pico_history.py` 必须放在同一个目录。PyInstaller 打包入口仍为 `jsondecode.py`，会自动收集导入的传输模块；旧版 Release 可执行文件需要重新打包才会包含修复。

## 大容量历史读取

“读取设备记录”和“导出日志到电脑”共用 `pico_history.download_history()`：

- 同一个串口会话中暂停程序、进入 raw REPL 并软复位，停止接收线程和定时器，避免运行日志混入传输。
- 以二进制方式每次读取最多 4096 字节，每个事务有独立 EOF 与 20 秒响应超时；不再限制整份文件必须在 30/45 秒内完成。
- 显示百分比和已传字节数；电脑与设备分别增量计算 SHA-256，核对长度、文件尾和摘要。设备不将整份历史载入内存。
- 读取成功后才解码 UTF-8；传输失败不会将部分数据载入查看器。导出先写本机临时文件，成功后才原子替换用户选择的目标。
- 成功或异常均尝试发送硬件重启指令恢复原程序，恢复指令失败会明确提示手动复位。指令发送成功不等于已确认完成 POST，请检查设备回到主页。
- 不写入、删除或格式化设备上的历史、索引、配置或固件。下载期间不接收新车次，未落盘的运行状态会因复位丢失；传输完成前请勿关闭软件或拔 USB。

原实现的 `mpremote cat` 连续输出整个文件，且主进程另设 30 秒读取/45 秒导出限制。`timeout waiting for first EOF reception` 来自 mpremote 等待远端命令 stdout 结束的传输层，不是 JSON 解析错误，也不能仅凭此认定历史文件损坏。新实现缩短单次输出、显式控制超时并验证完整性，不依赖增加整份 `cat` 的等待时间。

## 测试

在仓库根目录运行：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s log-viewer/tests -v
```

涵盖 9999 条、超过 3 MB 的合成历史、中文跨块、空文件、提前 EOF、断连、截断、尺寸变化、同长度数据损坏、恢复失败、导出原子替换及查看器接入。合成测试不等同于实机测试。

### 2026-09-08 实机验证

- 已连接的 W 设备：9999 条，2,722,654 字节；分块下载、完整性校验和恢复指令共 30.296 秒。
- SHA-256：`409e765d68c021333fe1fc389e387ea25806a4544a3d174250c4c575cd25d94d`，与此前设备全量扫描一致；本机原子导出的文件摘要也一致。
- 真实数据通过查看器 `extract_log_info()` 全量解析：9999 条，首尾时间分别为 `11:18:00` / `14:12:43`。
- 重启后重新观察到 `RADIO_CFG`、`LBJ_RESYNC`、`LBJ_ALIGN` 接收日志；随后 `RADIO_HEALTH` 显示 `words=4371`，接收线程、SPI、回调、存储和 Wi-Fi 错误均为 0，接收/UI/历史待处理队列为 0。未改固件、历史或索引。
- 此测试环境不能调用 `termios.tcsetattr`，因此实机验证使用获准的 USB 字节读写适配器；运行的是同一个 `download_history()` 与真实 mpremote 协议。未在这个环境中验证 pyserial 的串口参数配置、完整图形界面或旧版打包可执行文件。
- 23 项自动化测试通过。旧版用户环境的同一次 EOF 故障未独立复现；30.296 秒是新分块流程耗时，不能直接当作旧版 `cat` 耗时。
