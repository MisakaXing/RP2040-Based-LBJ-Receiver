# PicoUpdater

运行 `python3 pico_updater.py`。依赖：`customtkinter requests pyserial mpremote`。

## 串口安全

扫描未发现 Pico VID `0x2E8A` 时，不再默认选择列表中的蓝牙/其他串口，刷入和检查按钮保持禁用。仍可手动选择第三方固件使用的其他 USB VID，但启动操作前必须确认“所选串口未识别为 Pico”（默认否）。每次启动都会重新确认所选串口仍存在；断开后不会自动改用另一个串口继续任务。USB VID 仅用于候选选择，不能替代刷入前已有的板型与固件兼容检查。

## 焊接检查单

核心页使用 RTC、射频 SPI、射频时钟/数据线、电池电压四行检查单，按设备实时事件显示等待、动态检查中、通过、失败或跳过。底部“展开详细日志”默认收起，随时可展开查看；全部完成后停留，仍需点击“确认结果，继续”。

核心检查实时滚动输出日志，通过后停留在日志页，必须点击“确认结果，继续”才开始按键采样；五键通过自动播放屏幕测试；用户确认画面正常后进入蜂鸣器页，通过中央大按钮手动单次试响。试响结束只就地更新按钮和次数，不隐藏或重排整个页面。确认听到后进入 SD 页，给出插卡提示并在 5 秒后自动检查，未插卡可跳过或失败后重试。失败不会自动判为通过。最终报告为带统计和状态色的检查单卡片，详细日志单独展开；可导出 HTML 或文本报告。

选择串口，点击“运行硬件自检”，检查单直接显示在主窗口运行日志区，不另开窗口；版本卡片和任务进度暂时收起。结束时释放串口并重启设备，报告可在原区域展开详细日志；点击“返回运行日志”恢复原布局和保留的日志，开始其他任务也会自动恢复。点击开始前会确认暂停接收和软复位；未落盘的临时数据可能丢失。不会刷固件、清历史或校时。

核心检查顶部独立显示设备 S/N（与固件相同的 12 位编码）、板型、MicroPython 版本及 CPU 频率。各项按真实串口事件更新，完成后保留当前检查单和日志展开状态，等待用户确认后继续。

1. **核心硬件**：沿用 RTC、射频 SPI、射频 CLK/DATA 检查，并自动读取电池电压（GP14 测量使能、GP27 ADC，8 次平均，按固件 `raw/65535*3.3*2+0.174` 换算）。电压显示在窗口顶部和报告中，不是精密测量；异常读数提示检查电池和分压接线。结果不是射频灵敏度认证。
2. **五键检查**：按用户实机反馈对调指示映射：GP2 MENU、GP4 UP、GP3 DOWN、GP5 OK、GP28 POWER，低电平有效。此为检查单映射，不改接收器固件。采样顺序从同一映射生成，避免图示与报告错位。先稳定松开，再稳定按下才计入通过；一直短路到地不会自动通过。90 秒未完成可重试，全部通过后自动进入屏幕页。
3. **屏幕检查**：自动显示 RGB、白、黑、网格、边框文字，之后必须由用户确认是否正常，不会因脚本运行成功就判定屏幕通过。
4. **蜂鸣器**：每点一次“响一下”，GP22 输出一次 120 ms 短响，结束保证回到低电平。由用户点击“听到了”或“未听到”判断结果，可重复试响或跳过。
5. **SD 卡**：提示插卡后 5 秒自动开始，初始化 SPI、读取容量和第 0 扇区。只读、不挂载、不格式化；不代表文件系统或写入能力已验证。

每项可跳过；失败后继续仍保留失败结果，跳过和未检查都不算通过。运行中的跳过会等待当前有限时长的操作结束；按键采样可主动取消。结束后发送硬重启恢复原程序（空板没有主程序），并显示可保存的 UTF-8 文本报告。连接或恢复失败会明确报告，不伪报成功。

外壳图示根据 `Case/CASE_V13_BODY_PCB_CLEARANCE_0p25.stl`、`CASE_V13_TOP_SCREEN_EDGE_IN0p7_TOTAL.stl` 的尺寸/开孔与用户照片绘制，为横屏正投影示意，而非可旋转的精确三维查看器。主体边界约 99.84 × 66.60 × 27 mm；根据用户最终确认，四键在左，POWER 在图的右侧、与 OK 水平对齐。

`diagnostic_drivers/` 是本项目 ILI9341 和 SDCard 驱动的诊断副本，在设备 RAM 执行，允许未刷主程序的板子检测。没有复制用户固件或存储数据到设备。若打包可执行文件，须把整个 `diagnostic_drivers` 作为数据目录一并包含，并确保 `solder_check` 与 `mpremote.transport_serial` 被打包。

测试：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests`。
