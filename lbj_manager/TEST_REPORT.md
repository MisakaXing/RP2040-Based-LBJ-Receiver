## 已覆盖

- 全局串口任务锁：40 个线程同时抢占只能有一个持有者；旧任务、伪造同值令牌不能解除新任务锁。
- 设备选择：单 Pico 首次选择、启动后插入并点击扫描、多 Pico 手动选择、非 Pico 串口、Debug Probe、拔出和更换设备；后台扫描不自动替换操作目标。点击扫描会给出完成 / 未发现 / 多台 / 失败提示；扫描失败禁用操作，重试成功恢复。
- 自动选中提示：启动时与点击扫描时，顶部选择器旁持续显示绿色「✓ 已自动选中 Pico」与端口；底部同时给出文字确认。后台扫描不抹掉提示；手动选择显示「已选中 Pico」，断开或扫描失败不保留绿色确认。
- 导航快捷键修复：用户在 Windows 实机复现并确认旧 `<Command-1>` 被解析为鼠标按钮，导致点击历史后又切回设备页。本地改为按平台选择 Command / Control，显式 `KeyPress-1/2`。测试检查两平台绑定字符串、页面目标及无含糊数字绑定；真实 Tk 测试向导航按钮 Label 注入鼠标按下 / 松开事件，验证来回切页，并在 Mac Tcl 引擎中验证 Ctrl 数字键事件。这不等同于本机完成 Windows 操作系统实测。
- 文件拖放：通过真实 TkDND 的 macOS enter / position / drop 事件链验证区域、按钮及其 Canvas / Label 子控件。中文、空格、花括号与大写后缀；单文件、类型 / 区域错误、损坏 ZIP、分支不符、设备忙碌；ZIP 仅载入、再次点击才进入既有预检确认，分支切换清除已载入包；日志直接导入、无效记录保持原数据，线程失败释放加载状态。明确禁止串口、刷写与设备历史命令。
- 主线程调度：1000 个后台回调有序执行，不从后台调用 Tk；任务失效、窗口关闭和回调超量不会误执行更新。
- 更新与恢复：取消、兼容性拒绝、线程启动失败、命令无输出或没有换行时的超时、USB 恢复失败、部分刷写、刷写中关闭窗口。
- 重启专项：重启不跟随 EOF、不退出旧 raw REPL，关闭旧串口后仅枚举 USB。Windows `ClearCommError`、发送失败、关闭失败、枚举失败、断开后未返回、未观察到断开均不能误报确认；同一 USB 序列号变更 COM 端口可识别，其他接收器不能冒充。在线与 ZIP 刷入共用完成提示；复制失败不发送重启，重启待确认不重复发送，警告只弹一次，普通写入错误仍失败。
- 固件包：普通 / W 两分支的在线清单、平铺 / GitHub 目录 / Windows 分隔符 ZIP；DMA 与保护模块先于 `main.py` 写入；直接读取两工作树的当前固件生成 ZIP，逐文件对照提取内容。
- 开机文件交付修复：移除旧测试中错误的“W 清单不包含 boot.py”断言。两版实际固件 ZIP 必须保留含 `LOADING FIRMWARE` 的 boot.py；新增测试覆盖 W 在线下载完整字节、两版三种 ZIP 路径、在线与 ZIP 两种清空/复制工作流（共 12 组子场景），验证 boot.py 写在 main.py 前，模拟设备启动交接保留画面。新版缺 boot.py 在确认之前拒绝；boot.py 写入失败保持部分刷入警告、不写 main.py、不重启。无交接的旧固件仍可刷入，注释/普通字符串不误判，语法损坏或非 UTF-8 的 boot.py 拒绝。
- 新增文件负向测试：新固件缺 `pio_dma_rx.py` 或 `device_protection.py` 时在确认刷入之前拒绝；旧固件未导入这些模块时仍接受。语法损坏、无效 UTF-8、不可读源码拒绝；注释中的 import 不误判。
- 历史传输：4096 字节分段、完整长度与 SHA-256、中文跨块、数据损坏、截断、空文件、恢复失败、原子导出不覆盖旧文件、读取与更新不能同时启动。
- 历史展示：9999 条全部保留，`0D139`、中文车型、五位车号和 A/B、年/月/日时/分、未知速度 `---`、零值与非法坐标、跨午夜时间筛选。
- 真实 UI：9999 条分批渲染、筛选再恢复、150 次改变记录选择、80 次页面切换、最小窗口 1120×800、单地图标记、坐标与日期不裁切。
- 检查单：嵌入设备页、运行时不离开检查单、核心通过后等待确认、W 显示 VSYS、报告结束释放锁并返回运行日志。原有按键、屏幕、蜂鸣器、SD 工作流回归测试保留。
- 打包：arm64 可执行文件、权限、Framework 符号链接、bundle 本地完整性、内嵌 mpremote、任意工作目录启动、复制整个 `.app` 后再次启动。检查可执行文件的归档，确认包含新合并 UI 与固件依赖验证函数。

快捷键修复首轮真实 GUI 压力测试：9999 条导入并渲染约 **1.00 秒**，全程约 10.50 秒；5 ms UI 心跳的最大间隔为 **148.3 ms**（不计截屏）。这些是本机测试值，不保证其他 Mac 同速。

## 边界

本轮**没有打开真实接收器串口、刷写设备、清除历史或修改射频 / 屏幕固件**。GUI 的 USB、下载与检查结果为模拟数据，不把模拟通过当作真实硬件合格。真实 USB 刷写、射频接收性能、实体按键与屏幕结果仍需后续设备联调。

重启专项在 Mac 上以模拟传输和 USB 枚举测试 Windows / macOS 分支，没有 Windows 主机或实体 USB 重连测试。USB 重连确认不代表新固件主程序或射频已启动正常；用户仍需检查屏幕与接收状态。此前 App / exe 不包含本次修复，不能继续使用旧包来验证工具修复；Windows exe 尚未重新打包。

前轮扫描专项另用 Mac 实际枚举到的 `/dev/cu.usbmodem1101` 验证了真实按钮：先重现“启动后才插入”的未选择状态，再点击扫描，确认选中、提示结果、更新 / 自检 / 读取按钮启用。测试显式禁止串口打开、设备命令与历史传输；接收器未暂停或复位。本轮目录替换及拖放更新后再次尝试扫描专项，电脑未检测到 Pico，测试在启动 GUI 前退出；本轮扫描行为由真实窗口加模拟枚举覆盖。

固件复制仍沿用 mpremote 文件复制结果，尚未加入设备端逐文件读回哈希；依赖检查不等同于刷入后的字节校验。历史导出已有 SHA-256 校验。

App 没有开发者证书签名或公证，使用打包器必需的本地 ad-hoc 完整性签名。复制启动测试发生在本 Mac，不等同于已在另一台 Mac 验证 Gatekeeper 放行。

拖放专项调用原生库实际使用的 Tcl 事件入口并经过真实绑定与异步解析；不是只有 Python 回调模拟，但未代替用户在 Finder 中手动拖动的最终体验确认。

本次快捷键最后一轮 GUI 测试的历史页、最小窗口及模拟检查单截图命令返回失败，已记录 `screenshot_warnings`；65 项状态与事件检查通过，但这轮截图不作为视觉验证成功证据。

原生 App 的强制结束测试在 stderr 记录了 Pillow `PhotoImage.__del__` 的忽略异常，启动阶段和窗口显示正常。测试脚本把启动阶段与测试强制 SIGTERM 后的日志分开保留；不能把所有退出路径都视为已验证无警告。
